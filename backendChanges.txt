Chef Voice Agent Backend

What This Backend Does
- FastAPI backend lives in backend/main.py.
- Uses Gemini to generate a short chef-agent response.
- Uses ElevenLabs Text to Speech to return playable MP3 audio.
- Also supports voice input: frontend sends an audio file, ElevenLabs Speech to Text transcribes it, Gemini responds, then ElevenLabs returns MP3 audio.

Environment
- Create backend/.env from backend/.env.example.
- Required keys:
  - GEMINI_API_KEY
  - ELEVENLABS_API_KEY
  - ELEVENLABS_VOICE_ID
- Do not commit backend/.env.


Git Ignore
- Generated audio files such as .mp3, .m4a, .wav, .webm, and .ogg are ignored by git.
- backend/.env, backend/.venv, and __pycache__ are ignored by git.

Endpoints

GET /health
- Confirms the server is running.
- Response:
  {
    "status": "ok"
  }

POST /chef/voice
- Text input fallback.
- Request JSON:
  {
    "text": "Why is my pasta sauce too watery?"
  }
- Response:
  - MP3 audio bytes
  - Content-Type: audio/mpeg

POST /chef/voice/audio
- Main voice-agent endpoint for the frontend.
- Request:
  - multipart/form-data
  - field name: file
  - value: recorded audio file/blob
- Response:
  - MP3 audio bytes
  - Content-Type: audio/mpeg

Frontend Integration

Use this endpoint for voice input:
http://localhost:8000/chef/voice/audio

Important:
- Send audio with FormData.
- Do not manually set Content-Type for FormData.
- Read the response with response.blob().
- Play the returned blob as audio.

Suggested helper:

async function sendVoiceRecording(audioBlob) {
  const formData = new FormData();
  formData.append("file", audioBlob, "recording.webm");

  const response = await fetch("http://localhost:8000/chef/voice/audio", {
    method: "POST",
    body: formData,
  });

  if (!response.ok) {
    const errorText = await response.text();
    throw new Error(errorText);
  }

  const replyAudioBlob = await response.blob();
  const replyAudioUrl = URL.createObjectURL(replyAudioBlob);
  const audio = new Audio(replyAudioUrl);
  await audio.play();

  return replyAudioUrl;
}

Suggested microphone flow:

let recorder;
let chunks = [];

async function startRecording() {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  recorder = new MediaRecorder(stream);
  chunks = [];

  recorder.ondataavailable = (event) => {
    chunks.push(event.data);
  };

  recorder.onstop = async () => {
    const audioBlob = new Blob(chunks, { type: "audio/webm" });
    await sendVoiceRecording(audioBlob);
  };

  recorder.start();
}

function stopRecording() {
  recorder.stop();
}

Recommended frontend UI states:
- idle: user can start recording
- recording: mic is active
- loading: backend is transcribing/responding/generating audio
- playing: response audio is playing
- error: request failed, let user retry

Testing From Terminal

Windows PowerShell text input test:
Invoke-WebRequest `
  -Uri "http://localhost:8000/chef/voice" `
  -Method POST `
  -ContentType "application/json" `
  -Body '{"text":"Why is my pasta sauce too watery?"}' `
  -OutFile "test.mp3"

Windows PowerShell audio input test:

curl.exe -X POST "http://localhost:8000/chef/voice/audio" -F "file=@rec.m4a" --output voice-response.mp3

Mac/Linux text input test:
curl -X POST "http://localhost:8000/chef/voice" \
  -H "Content-Type: application/json" \
  -d '{"text":"Why is my pasta sauce too watery?"}' \
  --output test.mp3

Mac/Linux audio input test:
curl -X POST "http://localhost:8000/chef/voice/audio" \
  -F "file=@rec.m4a" \
  --output voice-response.mp3
