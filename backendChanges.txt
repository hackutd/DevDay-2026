Chef Voice Agent Backend

Backend Location
- backend/main.py

What It Does
There are 2 main endpoints the frontend can call from a voice assistant popup/modal:
- Text input: text -> Gemini -> ElevenLabs TTS -> MP3 audio response
- Voice input: audio file -> ElevenLabs STT -> Gemini -> ElevenLabs TTS -> MP3 audio response

API Contract

GET /health
- Purpose: check if backend is running.
- Response:
  { "status": "ok" }

POST /chef/voice
- Purpose: text fallback endpoint.
- Request:
  Content-Type: application/json
  {
    "text": "Why is my pasta sauce too watery?"
  }
- Response:
  Content-Type: audio/mpeg
  Body: MP3 audio bytes

POST /chef/voice/audio
- Purpose: main frontend voice-agent endpoint.
- Request:
  Content-Type: multipart/form-data
  field name: file
  field value: recorded audio file/blob
- Response:
  Content-Type: audio/mpeg
  Body: MP3 audio bytes

POST /favorites/toggle
- Purpose: toggle a food item in the user's Firestore favorites.
- Request:
  Content-Type: application/json
  {
    "userId": "firebase-user-uid",
    "food": {
      "id": "53050",
      "name": "Ayam Percik",
      "image": "https://www.themealdb.com/images/media/meals/020z181619788503.jpg",
      "price": "$$",
      "category": "chicken"
    }
  }
- Response:
  Content-Type: application/json
  {
    "favorites": []
  }

Frontend Notes
- For /chef/voice/audio, send FormData.
- Do not manually set Content-Type when sending FormData.
- Read successful responses with response.blob().
- Play the returned Blob with URL.createObjectURL().
- Recommended UI states: idle, recording, loading, playing, error.

Frontend Voice Helper

async function sendVoiceRecording(audioBlob) {
  const formData = new FormData();
  formData.append("file", audioBlob, "recording.webm");

  const response = await fetch("http://localhost:8000/chef/voice/audio", {
    method: "POST",
    body: formData,
  });

  if (!response.ok) {
    throw new Error(await response.text());
  }

  const replyAudioBlob = await response.blob();
  const replyAudioUrl = URL.createObjectURL(replyAudioBlob);
  await new Audio(replyAudioUrl).play();

  return replyAudioUrl;
}

Frontend Recording Shape

let recorder;
let chunks = [];

async function startRecording() {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  recorder = new MediaRecorder(stream);
  chunks = [];

  recorder.ondataavailable = (event) => {
    chunks.push(event.data);
  };

  recorder.onstop = async () => {
    const audioBlob = new Blob(chunks, { type: "audio/webm" });
    await sendVoiceRecording(audioBlob);
  };

  recorder.start();
}

function stopRecording() {
  recorder.stop();
}


TO RUN:

Environment
- Create backend/.env from backend/.env.example.
- Required keys:
  - GEMINI_API_KEY
  - ELEVENLABS_API_KEY
  - ELEVENLABS_VOICE_ID
  - FIREBASE_SERVICE_ACCOUNT_PATH
- Do not commit backend/.env.
- Do not commit backend/firebase-service-account.json.

Run Backend
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:app --reload

Useful URLs
- API docs: http://localhost:8000/docs
- Health check: http://localhost:8000/health

Firebase Favorites Backend

Current app behavior:
- Frontend already uses Firebase Auth for login/register/logout.
- Frontend currently writes favorites directly to Firestore from src/context/AppContext.js.
- Firestore shape is favorites/{userUid} with an items array.

Backend behavior:
- Move favorite add/remove logic behind the FastAPI backend.
- Keep this beginner-friendly by having the frontend send currentUser.uid as userId.
- Backend uses Firebase Admin SDK to write to Firestore.
- Production version would verify a Firebase ID token instead of trusting userId from the frontend.

Backend files:
- backend/firebase_service.py handles Firebase setup and Firestore helper functions.
- backend/main.py has POST /favorites/toggle.
- backend/requirements.txt includes firebase-admin.

Firebase Admin setup:
1. Go to Firebase Console.
2. Open the project used by the frontend.
3. Go to Project Settings.
4. Go to Service accounts.
5. Click Generate new private key.
6. Save the downloaded JSON file inside backend/.
7. Rename it to firebase-service-account.json.
8. Make sure this file is ignored by git.

Add this to backend/.env:
FIREBASE_SERVICE_ACCOUNT_PATH=./firebase-service-account.json

Frontend call shape:
await fetch("http://localhost:8000/favorites/toggle", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    userId: currentUser.uid,
    food,
  }),
});

Important:
- userId should be currentUser.uid from Firebase Auth.
- Backend writes to favorites/{userId}.
- This is simpler for a hackathon, but not secure for production because userId can be faked.
